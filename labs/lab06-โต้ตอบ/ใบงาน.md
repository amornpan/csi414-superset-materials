## วัตถุประสงค์

1. แบ่งแดชบอร์ดเป็น **แท็บ** เพื่อแยกภาพรวมออกจากรายละเอียด
2. เปิด **Cross-filter** ให้คนอ่านคลิกกราฟหนึ่งแล้วกราฟอื่นกรองตาม
3. ใช้ **Drill to detail** และ **Drill by** เพื่อพิสูจน์ตัวเลขที่อยู่บนจอ
4. ส่งลิงก์แดชบอร์ดแบบ **ซ่อนเมนู** สำหรับฉายขึ้นจอ และ **ส่งออกข้อมูล** เป็นไฟล์

> ### แดชบอร์ดสัปดาห์ที่แล้วเป็นของที่ "ดู" ได้ สัปดาห์นี้จะทำให้มันเป็นของที่ "ใช้" ได้
>
> ความต่างคือ แดชบอร์ดที่ดูได้อย่างเดียวตอบได้แค่คำถามที่คนทำคิดไว้ล่วงหน้า
> ส่วนแดชบอร์ดที่โต้ตอบได้ ทำให้คนอ่าน **ตั้งคำถามใหม่ของตัวเองได้โดยไม่ต้องกลับมาหาคุณ**

## ตอนที่ 1 — แบ่งแท็บ (20 นาที)

1. เข้าโหมด **Edit dashboard**
2. ลากองค์ประกอบ **Tabs** จากแถบขวามาวางบนสุดของแดชบอร์ด
3. ตั้งชื่อแท็บให้เป็นภาษาคน อย่างน้อย **2 แท็บ**

| แท็บ | ควรใส่อะไร |
|---|---|
| **ภาพรวม** | ตัวเลขใหญ่ กราฟเส้น สิ่งที่ตอบคำถามหลักทันที |
| **เจาะลึก** | ตาราง ตารางไขว้ กราฟแท่ง สำหรับคนที่อยากหาสาเหตุ |

4. ลากกราฟที่มีอยู่แล้วเข้าไปในแท็บที่เหมาะสม **อย่าลบกราฟใด ๆ ทิ้ง**

> **แท็บแต่ละแท็บมี URL ของตัวเอง** คัดลอกจากช่องที่อยู่ตอนเปิดแท็บนั้น
> แล้วส่งให้คนอื่นเปิดตรงแท็บที่คุณต้องการได้เลย


## ตอนที่ 2 — เปิด Cross-filter (25 นาที)

1. ที่เมนูจุดสามจุดของแดชบอร์ด เลือก **Edit properties** แล้วเปิด **Enable cross-filtering**
   (บางรุ่นอยู่ที่เมนูจุดสามจุด ‣ **Enable cross-filtering** โดยตรง)
2. กลับมาที่หน้าแดชบอร์ด แล้ว **คลิกที่แท่งของชั้นโดยสารหนึ่งชั้น** บนกราฟแท่งของคุณ
3. สังเกตว่ากราฟอื่นเปลี่ยนตามหรือไม่

**บันทึกผล**

| คลิกที่ | กราฟที่เปลี่ยนตาม | กราฟที่ไม่เปลี่ยน |
|---|---|---|
| แท่ง Business บนกราฟแท่ง | | |
| แถวหนึ่งบนตาราง | | |

4. กดปุ่มล้างตัวกรองที่มุมบนเพื่อยกเลิก

> **Cross-filter ต่างจาก Native Filter ตรงที่ใครก็ตั้งได้ทันทีด้วยการคลิก**
> Native Filter คือคำถามที่คุณเตรียมไว้ให้ ส่วน Cross-filter คือคำถามที่คนอ่านคิดเองหน้างาน

## ตอนที่ 3 — เจาะลึกเพื่อพิสูจน์ตัวเลข (20 นาที)

**Drill to detail** — คลิกขวาที่จุดข้อมูลหนึ่งจุดบนกราฟ แล้วเลือก **Drill to detail**

| คำถาม | คำตอบของคุณ |
|---|---|
| ตัวเลขที่คุณคลิก มาจากข้อมูลกี่แถว | |
| แถวแรกที่เห็น เป็นการเดินทางของแผนกอะไร | |
| กดปุ่ม Download ในหน้าต่างนี้ได้ไฟล์อะไร | |

**Drill by** — คลิกขวาที่จุดเดิม เลือก **Drill by** แล้วเลือกคอลัมน์ `Department`

| คำถาม | คำตอบของคุณ |
|---|---|
| ตัวเลขเดิมถูกหั่นออกเป็นกี่ส่วน | |
| ส่วนที่ใหญ่ที่สุดคือแผนกอะไร | |

**View query** — ที่เมนูจุดสามจุดของกราฟ เลือก **View query** แล้วอ่าน SQL ที่ระบบสร้าง

> **นี่คือเครื่องมือที่ทำให้เถียงกันเรื่องตัวเลขจบได้**
> เวลามีคนบอกว่า "ตัวเลขนี้ผิดแน่ ๆ" คุณเปิด Drill to detail ให้เขาดูแถวจริงได้ทันที
> แทนที่จะเถียงกันด้วยความรู้สึกว่าใครน่าเชื่อถือกว่า


## ตอนที่ 4 — ลิงก์สำหรับฉายขึ้นจอ และการส่งออกข้อมูล (20 นาที)

**ลิงก์แบบซ่อนเมนู** คัดลอก URL ของแดชบอร์ดคุณ แล้วเติมพารามิเตอร์ต่อท้าย

| พารามิเตอร์ | ผล |
|---|---|
| `?standalone=1` | ซ่อนแถบเมนูด้านบน |
| `?standalone=2` | ซ่อนแถบเมนูและชื่อแดชบอร์ด |
| `&show_filters=0` | ไม่แสดงแถบตัวกรอง |

ลองเปิดลิงก์ `?standalone=1&show_filters=0` แล้วจดไว้ว่าหน้าจอต่างจากเดิมอย่างไร

**ส่งออกข้อมูล** ที่เมนูจุดสามจุดของกราฟตาราง เลือก **Download ‣ Export to original .CSV**

> **ข้อควรระวังที่คนพลาดบ่อย** ถ้ากราฟตารางเปิดช่องค้นหาไว้และมีคำค้นค้างอยู่
> ปุ่ม Download จะส่งออก **เฉพาะแถวที่เห็นบนจอ** ไม่ใช่ทั้งชุด
> ถ้าต้องการทั้งชุด ให้ล้างคำค้นก่อนเสมอ

## ตอนที่ 5 — สำรวจข้อมูลขั้นที่ 2: ตัวแปรกระจายตัวอย่างไร (30 นาที)

ทำบนแท็บ `สำรวจข้อมูล flights` ที่สร้างไว้สัปดาห์ที่แล้ว dataset `flights` (ฐาน `examples`)

### 5.1 Histogram ที่ดูไม่รู้เรื่อง แล้วทำให้รู้เรื่อง (15 นาที)

1. สร้างกราฟชนิด **Histogram** คอลัมน์ `DEPARTURE_DELAY` · Bins = 10 · Time Range `No filter` ตั้งชื่อ `การกระจาย delay <รหัสนักศึกษา>`
2. ดูรูป: ทำไมเห็นแท่งเดียวตรงซ้าย แล้วที่เหลือแบน → เพราะช่วงคือ −39 ถึง **1,380** นาที แท่งหนึ่งกว้าง 140 นาที
3. เพิ่ม Filter `DEPARTURE_DELAY <= 180` แล้วลอง Bins = 10 → 50 → 100 บันทึกว่ารูปเปลี่ยนอย่างไร
4. **ห้ามลืม**: การกรองครั้งนี้ทิ้งเที่ยวบินไป 557 เที่ยว ต้องเขียนกำกับที่ชื่อกราฟหรือคำอธิบาย

|---|---|---|
| 10 | | |
| 50 | | |
| 100 | | |

**ตัวเลขสองตัวที่เล่าคนละเรื่อง:** สร้าง Table ไม่มี dimension ใส่ metric `AVG(DEPARTURE_DELAY)` แล้วเทียบกับจุดกึ่งกลางของ histogram
ค่าเฉลี่ยคือ **16.8** นาที แต่ครึ่งหนึ่งของเที่ยวบินออกช้าไม่เกิน **2** นาที และ 22,282 เที่ยว **ออกก่อนเวลา** — ถ้ารายงานแค่ค่าเฉลี่ย คนอ่านจะนึกว่าทุกเที่ยวช้า 17 นาที

## บันทึกสัปดาห์นี้ (ต้องเขียน)

เปิดกล่อง Markdown บนแดชบอร์ดของคุณ แล้วเขียนต่อท้ายของเดิม

```markdown
## บันทึกสัปดาห์ที่ 6

(เขียนที่นี่ อย่างน้อย 60 ตัวอักษร)
```

**ห้ามลบบันทึกของสัปดาห์ก่อน** ตัวตรวจตรวจสะสม ลบแล้วตกย้อนหลัง
เหมือนลบกราฟเก่าทิ้ง

สิ่งที่ควรเขียนถึง

- คุณแบ่งกราฟเข้าแท็บไหนบ้าง และใช้เกณฑ์อะไรตัดสินว่ากราฟรูปหนึ่งควรอยู่แท็บใด
- Cross-filter กับ Drill to detail ช่วยคนอ่านคนละแบบอย่างไร ยกตัวอย่างสถานการณ์ที่ต้องใช้แต่ละอย่าง
- มีกราฟบนแดชบอร์ดของคุณรูปไหนที่ไม่ควรถูก cross-filter กรองตามหรือไม่ เพราะอะไร
- ค่าที่หายไปสัปดาห์ก่อน กลายเป็นค่าที่กระจายตัวสัปดาห์นี้: คุณสรุปการกระจายของ delay ว่าอย่างไร และตัวเลขไหนที่คุณจะไม่ใช้รายงานอีกต่อไป

> เขียนสิ่งที่ **เห็น** ไม่ใช่สิ่งที่ **ทำ**
> "ทำกราฟเส้นเสร็จแล้ว" ไม่ได้บอกอะไรกับคนอ่าน
> "เปลี่ยนจาก SUM เป็น AVG แล้วรูปเปลี่ยนไปคนละเรื่อง" บอก

**ตัวอย่างแนวการเขียน** — เขียนของคุณเองจากตัวเลข/สิ่งที่เห็นจริงบนแดชบอร์ด อย่าลอกทั้งดุ้น (ระบบลายนิ้วมือกันลอกจับความซ้ำได้ และคะแนนบันทึกให้กับการเขียนสิ่งที่คุณเห็นเอง)

> แบ่งเป็นแท็บภาพรวมกับแท็บเจาะลึก ใช้เกณฑ์ว่าใครดูและดูเพื่อตัดสินใจอะไร Cross-filter ให้คนอ่านคลิกกรองข้ามกราฟเองตอนมีคำถามเฉพาะหน้าที่เราไม่ได้เตรียมไว้ ส่วน Drill to detail เปิดแถวจริงเบื้องหลังตัวเลขเวลาต้องยืนยันข้อเท็จจริง กราฟตัวเลขสรุปรวมทั้งบริษัทไม่ควรถูก cross-filter กรองตาม เพราะมันคือค่าอ้างอิงที่ต้องคงที่ไว้ให้เทียบ
