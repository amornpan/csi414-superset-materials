# แผนสาย EDA สัปดาห์ 5–10 + สัปดาห์ 11 บทสรุป — สำรวจข้อมูล `flights` ทีละขั้นจนส่งต่อให้คนสร้างโมเดลได้ แล้วปิดด้วย Superset ในงานจริงและ AI ผ่าน MCP

> ร่างเพื่อพิจารณา 19 ก.ย. 2569 · ตัวเลขทุกตัวในเอกสารนี้ตรวจกับข้อมูลจริงบนเซิร์ฟเวอร์ของวิชาแล้ว
> (Superset 4.1.4 — อัปจาก 4.1.1 เมื่อ 19 ก.ย. 2569 · dataset `flights` ในฐาน `examples` ซึ่งเป็น SQLite 3.40 · นักศึกษาทุกคนมีสิทธิ์เข้าถึงแล้ว)

## หลักการ

- **ชุดข้อมูลเดียวตลอด 6 สัปดาห์** เพราะ EDA เป็นกระบวนการ ไม่ใช่เทคนิคเป็นชิ้น ๆ สิ่งที่พบสัปดาห์นี้กำหนดสิ่งที่ทำสัปดาห์หน้า
- **สายเดิม (`tutorial_flights` + ตัวตรวจอัตโนมัติ) ไม่เปลี่ยน** สาย EDA ใส่เป็นตอนท้ายของแล็บ ~35 นาที บนแท็บ `สำรวจข้อมูล flights` ของแดชบอร์ดใบเดิม
- **ถามด้วย SQL → ดูด้วยกราฟ → ตัดสินใจ** (เพิ่ม 19 ก.ย. 2569) SQL Lab ใช้ทุกสัปดาห์ตั้งแต่สัปดาห์ 5 ไม่ใช่รอถึงสัปดาห์ 8 — รายละเอียดในหัวข้อ "SQL Lab ในสาย EDA"
- **ทุกสัปดาห์จบด้วยการตัดสินใจ ไม่ใช่แค่การเห็น** จดลง Decision log (สิ่งที่พบ · หลักฐาน · ตัดสินใจ · เหตุผล) สะสมจนเป็นใบสรุปสัปดาห์ 10
- **คาบทฤษฎีสอนแนวคิด คาบแล็บลงมือ ควิซถามการอ่านกราฟ** ของขั้นเดียวกันในสัปดาห์เดียวกัน
- **`video_game_sales` ใช้สาธิตในคาบทฤษฎีเท่านั้น** อาจารย์ทำให้ดูบนชุดหนึ่ง นักศึกษาทำเองบนอีกชุดหนึ่ง

## สัปดาห์ 7 — ค่าไหนสุดโต่ง และเป็นของจริงหรือข้อมูลผิด

| | |
|---|---|
| **คำถาม EDA** | outlier อยู่ไหน มีกี่ตัว เชื่อได้ไหม จะทำอะไรกับมัน |

| **นักศึกษาค้นพบเอง** | AA: Q3 = 30, ขอบบน 1.5×IQR = 79.5, นอกขอบ 423 เที่ยว แต่ VX ขอบบนแค่ 18.5 — "outlier" ขึ้นกับกลุ่ม · 5 อันดับแรก 1,112–1,380 นาที มี delay ขาเข้าใกล้เคียงกันทุกแถว จึงเป็นของจริง ไม่ใช่พิมพ์ผิด · ค่าลบสุด −39 คือออกก่อนเวลา ไม่ใช่ error |

## สัปดาห์ 8 — ยืนยันสิ่งที่ตาเห็นด้วยตัวเลข และสร้างชุดข้อมูลที่พร้อมใช้

| | |
|---|---|
| **คำถาม EDA** | ที่เห็นมา 3 สัปดาห์จริงแค่ไหน · นิยาม "ล่าช้า" ให้ทั้งทีมใช้เหมือนกันคืออะไร |
| **SQL Lab** (SQLite) | รันซ้ำ Saved Query `eda5` `eda6` `eda7` ให้ได้เลขเดิม · (1) ตรวจแถวซ้ำ `COUNT(*)` vs `COUNT(DISTINCT ds||AIRLINE||FLIGHT_NUMBER||ORIGIN_AIRPORT)` → 0 (2) Pearson r จากสูตร `(nΣxy − ΣxΣy) / sqrt((nΣx² − (Σx)²)(nΣy² − (Σy)²))` — ได้ 0.95 (`eda8_ตรวจซ้ำ`) · การนับ null และเปอร์เซ็นไทล์ย้ายไปทำตั้งแต่สัปดาห์ 5–6 แล้ว |
| **Virtual dataset `flights_clean`** (ข้อกำหนดสัปดาห์ 8) | `SELECT rowid AS id, *, SCHEDULED_DEPARTURE/100 AS dep_hour, CASE WHEN ARRIVAL_DELAY >= 15 THEN 1 ELSE 0 END AS is_delayed, CASE WHEN DEPARTURE_DELAY > 180 THEN 1 ELSE 0 END AS is_outlier FROM flights WHERE CANCELLED = 0 AND DIVERTED = 0` → 53,751 แถว = ผลของการตัดสินใจสัปดาห์ 5 และ 7 กลายเป็นของจริง |
| **Metric กลาง** (ข้อกำหนดสัปดาห์ 8) | `on_time_rate = AVG(1 − is_delayed)` นิยามไว้ที่ dataset ให้ทุกกราฟใช้ตัวเดียวกัน — VX 86.2% … MQ 46.7% |
| **แนวคิดในคาบทฤษฎี** | ทำไมนิยาม metric ต้องอยู่ที่เดียว (semantic layer) · reproducibility: การตัดสินใจใน EDA ต้องกลายเป็นโค้ดที่รันซ้ำได้ ไม่ใช่กดในหัว |
| **ตัดสินใจ** | ทุกกราฟตั้งแต่สัปดาห์ 9 ใช้ `flights_clean` เท่านั้น · "ล่าช้า" = ถึงช้า ≥ 15 นาที ตามนิยามของ BTS ที่ข้อมูลใช้อยู่แล้ว (สาเหตุความล่าช้าถูกบันทึกที่เกณฑ์นี้พอดี) |
| **ควิซ** | ให้ SQL นับ null ถามผลลัพธ์ · ถามว่าทำไมต้องกรอง `CANCELLED = 0` ก่อนคำนวณ delay เฉลี่ย |
| **หมายเหตุ** | ตรงกับ Progress ของโปรเจกต์ร่วม (12–17 ต.ค.) ทีมมีบันไดคำถาม + Decision log ไปใช้กับข้อมูลตัวเองได้พอดี |

## สัปดาห์ 9 — อะไรสัมพันธ์กับอะไร และ outlier บิดภาพแค่ไหน

| | |
|---|---|
| **คำถาม EDA** | ตัวแปรไหนไปด้วยกัน ตัวไหนซ้ำซ้อน ตัวไหนใช้ทำนายไม่ได้เพราะรู้ทีหลัง |
| **กราฟ** | **Bubble Chart** จาก `flights_clean` entity = `id` (จุดต่อแถวจริง กรองสายการบินเดียวก่อนเพื่อไม่ให้หนัก) 3 คู่: `DISTANCE`~`AIR_TIME` · `DEPARTURE_DELAY`~`ARRIVAL_DELAY` ลงสีด้วย `is_outlier` · `DISTANCE`~`ARRIVAL_DELAY` · Scatter แบบรวมค่า: `dep_hour` กับ `on_time_rate` · **แผนที่ deck.gl** (ข้อกำหนดสัปดาห์ 9): จุดสนามบินต้นทาง ขนาด = จำนวนเที่ยว สี = delay เฉลี่ย |
| **นักศึกษาค้นพบเอง** | ระยะทางกับเวลาบิน r = 0.976 เกือบเป็นเส้นตรง = ตัวแปรซ้ำซ้อน ใส่ทั้งคู่ในโมเดลไม่ได้อะไรเพิ่ม · delay ขาออกกับขาเข้า r = 0.95 แต่ **รู้ delay ขาออกได้ก็ต่อเมื่อเครื่องออกไปแล้ว** = leakage ถ้าจะทำนายล่วงหน้า · ระยะทางกับ delay r = −0.015 ไม่เกี่ยวกันเลย · ชั่วโมงกับสัดส่วนล่าช้า 11.6% → 49% ชัดที่สุดในชุด · ATL 3,202 เที่ยว delay เฉลี่ย 13.2 แต่ DFW 2,766 เที่ยว 33.0 · สนามบิน 3 แห่งไม่ขึ้นบนแผนที่ (จดไว้ตั้งแต่สัปดาห์ 5) |
| **แนวคิดในคาบทฤษฎี** | อ่าน scatter: ทิศทาง ความแรง รูปทรง · correlation ≠ causation · leakage · แผนที่คือ scatter ที่แกนเป็นพิกัด |
| **สาธิตด้วย `video_game_sales`** | `NA_Sales`~`EU_Sales` เห็นความสัมพันธ์บวกแต่มี Wii Sports ดึงมุมกราฟ ลองกรองออกแล้วดูว่ารูปเปลี่ยนไหม |
| **ตัดสินใจ** | เลือกตัวแปรที่รู้ก่อนออกเดินทางเท่านั้นสำหรับโมเดลทำนาย (`dep_hour`, `AIRLINE`, `ORIGIN_AIRPORT`, `DISTANCE`, `DAY_OF_WEEK`) · ตัด `AIR_TIME` (ซ้ำกับ `DISTANCE`) และ `DEPARTURE_DELAY`/`TAXI_OUT`/`WHEELS_OFF` (รู้ทีหลัง) |
| **ควิซ** | ให้ scatter 3 รูป จับคู่กับค่า r · ถามว่าตัวแปรไหนใช้ทำนายล่วงหน้าไม่ได้และเพราะอะไร |
