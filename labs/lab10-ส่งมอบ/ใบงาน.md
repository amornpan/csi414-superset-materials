## ตอนที่ 1 — แคชที่ตั้งให้ตรงกับความจริง (20 นาที)

ตั้งแคชบน **Dataset เสมือนของคุณเอง** ที่สร้างไว้สัปดาห์ 8 (เช่น `tutorial_flights_<รหัส>` หรือ `flights_clean_<รหัส>`)
**ไม่ใช่** `tutorial_flights` ตัวกลาง — ตัวกลางเป็นของผู้ดูแลระบบ คุณแก้ไม่ได้ ระบบจะปฏิเสธตอนกดบันทึก

1. ไปที่ **Datasets** เปิด **Edit dataset** ของ Dataset เสมือนของคุณ
2. ที่แท็บ **Settings** หาช่อง **Cache timeout** (ถ้าไม่เห็น กดเปิดส่วน **Advanced**) แล้วใส่ `3600` (หนึ่งชั่วโมง) แล้วกด **Save**
3. ทางเลือก: ตั้งรายกราฟก็ได้ — เปิดกราฟที่บันทึกแล้วในหน้า Explore กดปุ่ม **⋯** มุมขวาบน (ถัดจากปุ่ม Save)
   เลือก **Edit chart properties** แล้วหาช่อง **Cache timeout** ใต้หัวข้อ **Configuration** (คอลัมน์ขวา) ใส่ `3600` แล้วกด **Save**
   (เว้นว่าง = ใช้ค่าของ Dataset · `-1` = ไม่ใช้แคช)
4. เปิดแดชบอร์ดแล้วสังเกตว่าโหลดครั้งที่สองเร็วกว่าครั้งแรกไหม
5. กดเมนู **⋮** ที่มุมขวาบนของกราฟบนแดชบอร์ด แล้วดูบรรทัดบนสุด
   ระบบจะบอกว่า **Fetched … ago** (เพิ่งดึงจากฐานข้อมูล) หรือ **Cached … ago** (ใช้ผลที่เก็บไว้) และมีปุ่ม **Force refresh** ให้ดึงใหม่ทันที

**คิดก่อนตั้ง — เติมตารางนี้**

| ข้อมูลแบบนี้ | ควรตั้งแคชเท่าไร | ถ้าตั้งนานเกินไปจะเกิดอะไร |
|---|---|---|
| ข้อมูลย้อนหลังที่ไม่เปลี่ยนแล้ว | | |
| ยอดขายที่อัปเดตทุกคืน | | |
| จำนวนคนในห้องที่อัปเดตทุกนาที | | |

> ### แคชคือการโกหกที่ตกลงกันไว้ล่วงหน้า
>
> เวลาตั้งแคชหนึ่งชั่วโมง คุณกำลังบอกว่า "ตัวเลขที่เก่าได้ถึงหนึ่งชั่วโมง ยังใช้ตัดสินใจได้"
> ถ้าข้อมูลจริงเปลี่ยนทุกนาที คนอ่านจะเห็นตัวเลขเก่า **โดยไม่มีอะไรบนหน้าจอบอกเขาเลย**
>
> Superset 4.1 ไม่มีป้ายเวลาที่แสดงบนกราฟตลอดเวลา คนอ่านต้องกดเมนู ⋮ ของกราฟเองถึงจะเห็น
> **เพราะฉะนั้นต้องเขียนความสดของข้อมูลไว้ในกล่อง Markdown** (ตอนที่ 4) และบอกวิธีกด Force refresh
> เพื่อให้คนอ่านรู้ว่าตัวเลขนี้เก่าได้แค่ไหน


## ตอนที่ 2 — คนอื่นเปิดได้จริงหรือเปล่า (25 นาที)

ทำเป็นคู่ — เรียกเจ้าของแดชบอร์ดว่า **A** และเพื่อนที่ลองเปิดว่า **B**

1. **A** เปิดแดชบอร์ด `csi414_<รหัส>` ของตัวเอง คัดลอก URL จากแถบที่อยู่ของเบราว์เซอร์ (`…/superset/dashboard/<เลข>/`) แล้วส่งให้ B ทางแชต
2. **B** เปิด URL นั้นด้วยบัญชีของตัวเอง — ตอนนี้แดชบอร์ดยังเป็น **Draft** — จดข้อความที่ขึ้นลงตารางข้างล่าง
3. **A** เปลี่ยนเป็น Published: ที่หน้าแดชบอร์ด (โหมดดูปกติ **ไม่ใช่** โหมด Edit — ในโหมด Edit ป้ายจะหายไป)
   มองหาป้ายสีเทาคำว่า **Draft** ทางขวาของชื่อแดชบอร์ด แล้ว **คลิกที่ป้ายนั้นหนึ่งครั้ง** ป้ายจะเปลี่ยนเป็น **Published** ทันที ไม่ต้องกด Save
   (ถ้าคลิกแล้วไม่เปลี่ยน แปลว่าคุณไม่ใช่เจ้าของแดชบอร์ดนั้น)
4. **B** กด F5 แล้วจดว่าเห็นกราฟครบไหม กราฟไหนขึ้น error และกดชื่อกราฟเพื่อเปิดใน Explore ได้ไหม
5. **สลับบทกัน** — B เป็นเจ้าของ A เป็นคนเปิด ทำข้อ 1–4 ซ้ำ
6. **A คลิกป้าย Published อีกครั้ง ให้กลับเป็น Draft** (B ก็เช่นกัน) — ต้องทำก่อนกดส่งงาน มิฉะนั้นระบบตรวจจะตก

| ทดสอบ | ผลที่ได้ |
|---|---|
| ตอนเป็น Draft: เพื่อนเปิด URL แล้วขึ้นอะไร | |
| หลัง Publish: เพื่อนเห็นกราฟครบไหม | |
| ถ้าเปิดไม่ได้ ระบบขึ้นข้อความว่าอะไร | |
| เพื่อนกดชื่อกราฟเพื่อเปิดใน Explore ได้ไหม | |

> **แดชบอร์ดที่ยังเป็น Draft คนอื่นมองไม่เห็น** แม้จะรู้ URL ก็ตาม
> นี่คือเหตุผลที่ใบงานทุกสัปดาห์สั่งว่าห้าม Publish — งานของคุณจึงไม่ถูกลอกโดยอัตโนมัติ

**สองเงื่อนไขที่ต้องครบ คนอื่นถึงจะเห็นแดชบอร์ดได้**

| เงื่อนไข | ตรวจอย่างไร |
|---|---|
| แดชบอร์ดต้อง Published | ดูป้ายข้างชื่อแดชบอร์ด |
| เขาต้องมีสิทธิ์เข้าถึง **Dataset** ที่แดชบอร์ดใช้ | ถามผู้ดูแลระบบ หรือให้เขาลองเปิด Dataset ตรง ๆ |

> **สิ่งที่น่าจะเห็นบนเซิร์ฟเวอร์ของวิชา**
>
> - กราฟที่ใช้ `tutorial_flights` ตัวกลาง เพื่อนเห็นได้ เพราะทุกคนมีสิทธิ์ใน Dataset นี้
> - กราฟที่ใช้ **Dataset เสมือนของคุณ** อาจขึ้นข้อความว่าไม่มีสิทธิ์เข้าถึงข้อมูล เพราะ Dataset นั้นเป็นของคุณคนเดียว = เงื่อนไขที่ 2 ไม่ครบ
> - กดชื่อกราฟเพื่อเปิดใน Explore **ไม่ได้** เซิร์ฟเวอร์ของวิชาตั้งให้นักศึกษาเปิดได้เฉพาะกราฟที่ตัวเองเป็นเจ้าของ เพื่อกันการ Save as ไปใช้ต่อ
>   ในองค์กรจริง ผู้ดูแลระบบจะให้สิทธิ์ผ่าน Role แทน
>
> ถ้าเห็นผลต่างจากนี้ ให้จดไว้ตามจริง แล้วเขียนถึงมันในบันทึกสัปดาห์นี้

## ตอนที่ 4 — เอกสารส่งมอบในกล่อง Markdown (15 นาที)

แก้กล่อง Markdown บนแดชบอร์ดให้ครบทั้งหกข้อนี้

1. เปิดแดชบอร์ด แล้วกด **Edit dashboard** มุมขวาบน
2. **คลิกในกล่อง Markdown** กล่องจะสลับเป็นข้อความดิบให้แก้ (ยังไม่มีกล่อง? ลาก **Text / Markdown** จากแท็บ **Layout elements** ทางขวามาวาง)
3. วางแม่แบบข้างล่างแล้วเติมให้ครบ — **ทุกข้อขึ้นต้นด้วย `- `** เพราะถ้าเขียนบรรทัดติดกันเฉย ๆ Superset จะรวมทั้งหกบรรทัดเป็นย่อหน้าเดียวยาวพรืด
4. คลิกที่ว่างนอกกล่องเพื่อดูผล แล้วกด **Save** มุมขวาบน

```markdown
## <ชื่อแดชบอร์ด>

- **คำถามที่ตอบ** ...
- **ข้อมูล** มาจากไหน ครอบคลุมช่วงไหน กี่แถว
- **หน่วย** ...
- **นิยาม metric** ค่าตั๋วเฉลี่ย คือ AVG(Cost) นับทุกเที่ยว ไม่ตัดตั๋วที่ยกเลิก
- **ความสดของข้อมูล** ตั้งแคชไว้เท่าไร เพราะอะไร · ต้องการตัวเลขล่าสุดให้กด ⋮ ‣ Force refresh
- **คนดูแล** ชื่อและวิธีติดต่อ
```

## ตอนที่ 5 — สำรวจข้อมูลขั้นสุดท้าย: สรุปให้คนสร้างโมเดลใช้ต่อ (30 นาที)

หกสัปดาห์ที่ผ่านมาคุณมีกราฟสำรวจ 10 กว่ารูปและ Decision log ยาวเหยียด **คนที่จะสร้างโมเดลไม่มีเวลาอ่านทั้งหมด** งานวันนี้คือย่อให้เหลือหนึ่งหน้า

### 5.1 รันซ้ำ แล้วคัดกราฟ (10 นาที)

ก่อนเขียนอะไร เปิด SQL → Saved Queries แล้ว **รัน `eda5` ถึง `eda9` ของคุณอีกรอบ** ตัวเลขทุกตัวที่จะลง Brief ต้องมาจากผลรันวันนี้ ไม่ใช่จากความจำ

เก็บไว้บนแท็บ `สำรวจข้อมูล flights` **ไม่เกิน 5 รูป** ที่เหลือเอาออกจากแท็บ (ตัวกราฟยังอยู่ ไม่ต้องลบทิ้ง) เกณฑ์คัด: รูปนั้นทำให้ **ตัดสินใจ** อะไรได้ ถ้าตอบไม่ได้ เอาออก

### 5.2 Data Understanding Brief (20 นาที)

เขียนกล่อง Markdown บนแท็บเดียวกัน ตามหัวข้อนี้ทุกข้อ

```markdown
## Data Understanding Brief — flights (1–4 ม.ค. 2015)

**เป้าหมายที่แนะนำ** is_delayed (ถึงช้า ≥ 15 นาที) — สัดส่วน 33.1% ไม่สมดุลระดับปานกลาง
**ตัวแปรที่น่าใช้** dep_hour · AIRLINE · ORIGIN_AIRPORT · DISTANCE · DAY_OF_WEEK (พร้อมเหตุผลจากกราฟสัปดาห์ 9)
**ห้ามใช้ (รู้ทีหลัง)** DEPARTURE_DELAY · TAXI_OUT · WHEELS_OFF · AIR_TIME (ซ้ำกับ DISTANCE) · คอลัมน์สาเหตุความล่าช้าทุกตัว
**ค่าหาย** 3 แบบ และวิธีจัดการแต่ละแบบ (สัปดาห์ 5)
**outlier** 552 แถวใน `flights_clean` flag ไว้ ไม่ลบ เพราะ... (สัปดาห์ 7)
**ข้อจำกัดที่ต้องบอกก่อนใช้** ข้อมูล 4 วันแรกของปี ช่วงวันหยุด ไม่แทนทั้งปี · สนามบิน 3 แห่งไม่มีพิกัด
**ตรวจซ้ำได้อย่างไร** SQL ของ `flights_clean` ทั้งก้อน + รายชื่อ Saved Query eda5–eda9 พร้อมตัวเลขหลักของแต่ละตัว
**Decision log ฉบับเต็ม** (คัดลอกตารางที่สะสมมาทั้ง 5 สัปดาห์)
```

> **exploratory → explanatory** สัปดาห์ 5–9 คุณทำกราฟให้ตัวเองเข้าใจ จะรกก็ได้ ขอให้เร็ว

## บันทึกสัปดาห์นี้ (ต้องเขียน)

เปิดกล่อง Markdown บนแดชบอร์ดของคุณ แล้วเขียนต่อท้ายของเดิม

```markdown
## บันทึกสัปดาห์ที่ 10

(เขียนที่นี่ อย่างน้อย 60 ตัวอักษร)
```

**ห้ามลบบันทึกของสัปดาห์ก่อน** ตัวตรวจตรวจสะสม ลบแล้วตกย้อนหลัง
เหมือนลบกราฟเก่าทิ้ง

สิ่งที่ควรเขียนถึง

- คุณตั้งแคชไว้เท่าไรและเพราะอะไร ถ้าข้อมูลชุดนี้อัปเดตทุกนาที คุณจะตั้งต่างไปอย่างไร
- คนที่รับงานของคุณไปทำต่อ ต้องรู้อะไรบ้างถึงจะทำงานต่อได้โดยไม่ต้องถามคุณ
- ตอนทดสอบด้วยบัญชีของเพื่อน คุณพบอะไรที่ไม่คาดคิด และมันเปลี่ยนวิธีที่คุณจะส่งมอบงานอย่างไร
- brief ของคุณบอกคนสร้างโมเดลว่าอะไรสำคัญที่สุดที่เขาต้องรู้ก่อนแตะข้อมูล และคุณตัดกราฟรูปไหนออกเพราะอะไร

> เขียนสิ่งที่ **เห็น** ไม่ใช่สิ่งที่ **ทำ**
> "ทำกราฟเส้นเสร็จแล้ว" ไม่ได้บอกอะไรกับคนอ่าน
> "เปลี่ยนจาก SUM เป็น AVG แล้วรูปเปลี่ยนไปคนละเรื่อง" บอก

**ตัวอย่างแนวการเขียน** — เขียนของคุณเองจากตัวเลข/สิ่งที่เห็นจริงบนแดชบอร์ด อย่าลอกทั้งดุ้น (ระบบลายนิ้วมือกันลอกจับความซ้ำได้ และคะแนนบันทึกให้กับการเขียนสิ่งที่คุณเห็นเอง)

> ตั้งแคช 1 ชั่วโมงเพราะข้อมูลปี 2011 ไม่เปลี่ยนแล้ว ถ้าเป็นข้อมูลที่อัปเดตทุกนาทีจะตั้งสั้นมากหรือไม่แคชเลย ไม่งั้นคนตัดสินใจจากตัวเลขที่ไม่จริง คนรับงานต่อต้องรู้ว่าแดชบอร์ดตอบคำถามอะไร ข้อมูลมาจากไหน และ metric กลางนิยามว่าอะไร ตอนทดสอบด้วยบัญชีเพื่อนพบว่าเพื่อนเห็นแดชบอร์ดไม่ได้เพราะยังเป็น Draft และไม่มีสิทธิ์ Dataset ต้อง Publish และให้สิทธิ์ก่อนถึงจะส่งมอบได้จริง
