สัปดาห์ละหนึ่งคำถาม ทุกอย่างที่พบจะถูกจดลง **บันทึกการตัดสินใจ** ท้ายใบงาน และสะสมไปจนกลายเป็น

### 5.2 ถามด้วย SQL ก่อน: คอลัมน์ไหนมีค่าหาย (10 นาที)

ตารางนี้มี 44 คอลัมน์ ถ้าสร้างกราฟนับทีละคอลัมน์จะหมดคาบก่อนรู้ว่าต้องดูตรงไหน
งานแบบ **กวาดดูทั้งตารางในครั้งเดียว** เป็นงานของ SQL Lab ส่วนกราฟเก็บไว้ใช้กับสิ่งที่ต้อง **เห็นรูป** หรือต้อง **อยู่บนแดชบอร์ดให้คนอื่นดู**

> **แบบแผนของสาย EDA ทุกสัปดาห์: ถามด้วย SQL → ดูด้วยกราฟ → ตัดสินใจ**
> SQL ให้ตัวเลขที่แม่นและรันซ้ำได้ กราฟให้รูปทรงที่ตัวเลขบอกไม่ได้
> ถ้าสองอย่างนี้ **ไม่ตรงกัน** นั่นคือข้อค้นพบ ไม่ใช่ความผิดพลาด

1. เมนู **SQL → SQL Lab** · Database `examples` · Schema `main` · ช่อง See table schema เลือก `flights` เพื่อดูรายชื่อคอลัมน์ทั้งหมด
2. วางคำสั่งนี้แล้วกด **Run** (หรือ Ctrl+Enter)

```sql
SELECT COUNT(*)                                AS rows_all,
       COUNT(*) - COUNT(DEPARTURE_DELAY)       AS dep_delay_null,
       COUNT(*) - COUNT(ARRIVAL_DELAY)         AS arr_delay_null,
       COUNT(*) - COUNT(CANCELLATION_REASON)   AS cancel_reason_null,
       COUNT(*) - COUNT(AIR_SYSTEM_DELAY)      AS air_system_delay_null,
       COUNT(*) - COUNT(AIRLINE)               AS airline_null
FROM flights
```

**กติกาที่ต้องรู้:** `COUNT(*)` นับทุกแถว แต่ `COUNT(คอลัมน์)` นับเฉพาะแถวที่คอลัมน์นั้น **มีค่า**
ดังนั้น จำนวนที่หาย = `COUNT(*)` − `COUNT(คอลัมน์)` (เขียนแบบนี้ใช้ได้ทั้ง SQLite ของ `examples` และ PostgreSQL ที่จะเจอในโครงงาน)

3. **เพิ่มเองอีกอย่างน้อย 3 คอลัมน์** ที่คุณอยากรู้ แล้วรันใหม่ — อย่าเลือกตามเพื่อน คอลัมน์ที่ไม่มีใครดูคือที่ที่ปัญหาซ่อนอยู่
4. กด **Save** ตั้งชื่อ `eda5_ค่าหาย_<รหัสนักศึกษา>` — query ที่บันทึกไว้คือ **หลักฐานที่รันซ้ำได้**
   เปิดดูได้ที่ SQL → Saved Queries และสัปดาห์ 8 จะเอากลับมาใช้

### 5.3 ดูด้วยกราฟ: ค่าที่หายอยู่ในกลุ่มไหน (12 นาที)

ตัวเลขจาก SQL อยู่ในหน้า SQL Lab ของคุณคนเดียว สิ่งที่จะอยู่บนแดชบอร์ดให้ทีมเห็นต้องเป็นกราฟ

สร้างกราฟชนิด **Table** จาก dataset `flights` · **Dimensions** = `CANCELLED` และ `DIVERTED` · ใส่ metric 3 ตัวนี้
(ทุกตัวเป็นแบบ Simple ไม่ต้องเขียน SQL)

| metric | Aggregate | คอลัมน์ | ตั้งชื่อว่า |
|---|---|---|---|
| 1 | COUNT | `*` | `เที่ยวบิน` |
| 2 | COUNT | `DEPARTURE_DELAY` | `มี delay ขาออก` |
| 3 | COUNT | `ARRIVAL_DELAY` | `มี delay ขาเข้า` |

Time Range `No filter` · ตั้งชื่อกราฟ `ค่าหายอยู่กลุ่มไหน <รหัสนักศึกษา>` แล้ววางบนแท็บ

คุณจะได้ตาราง 3 แถว ให้ลอกตัวเลขลงตรงนี้

| CANCELLED | DIVERTED | เที่ยวบิน | มี delay ขาออก | มี delay ขาเข้า |
|---|---|---|---|---|
| 0 | 0 | | | |
| 0 | 1 | | | |
| 1 | 0 | | | |

**ตอบจากตาราง**

1. เที่ยวบินที่ **ไม่ยกเลิกและไม่เปลี่ยนเส้นทาง** มีค่า delay ครบทุกแถวหรือไม่ → _____
2. เที่ยวบินที่ **เปลี่ยนเส้นทาง** (DIVERTED = 1) มีค่า delay ขาเข้ากี่แถว → _____ ทำไมถึงเป็นแบบนั้น
3. เที่ยวบินที่ **ยกเลิก** มีค่า delay ขาออก _____ แถวจาก _____ แถว
   แปลว่ามีเที่ยวบินที่ออกไปแล้วแต่ถูกนับว่ายกเลิก จริงหรือไม่ และคุณจะเชื่อค่า delay ของ 37 แถวนั้นไหม
4. บวกกันดู: delay ขาเข้าที่หาย 1,354 แถว = ยกเลิก _____ + เปลี่ยนเส้นทาง _____ ใช่หรือไม่
5. **เทียบกับ SQL:** คอลัมน์ `เที่ยวบิน` รวม 3 แถว = `rows_all` ของข้อ 5.2 ไหม → _____
   ถ้าไม่เท่า ให้เช็ก Time Range กับ Row limit ของกราฟก่อน — กราฟมีตัวกรองแฝงที่ SQL ไม่มี

> ถ้าบวกแล้วลงตัวพอดี แปลว่าคุณ **อธิบายค่าที่หายได้ทุกแถว** นี่คือสิ่งที่ต้องทำให้ได้ก่อนตัดสินใจอะไรกับมัน
> ค่าที่หายเพราะ "เที่ยวบินถูกยกเลิก" **ไม่ใช่ข้อมูลเสีย** มันหายเพราะไม่มีเหตุการณ์ให้วัด

### 5.4 ค่าที่หายเพราะกฎ ไม่ใช่เพราะเหตุการณ์ (8 นาที)

`AIR_SYSTEM_DELAY` หายไป 37,299 แถว มากกว่าครึ่ง แต่ไม่มีเที่ยวบินยกเลิกมากขนาดนั้น ต้องมีกฎอะไรบางอย่าง
กลับไป SQL Lab เปิดแท็บ query ใหม่ แล้วถามตรง ๆ ว่า **แถวที่มีสาเหตุ คือแถวแบบไหน**

```sql
SELECT ARRIVAL_DELAY >= 15        AS late_15,
       COUNT(*)                   AS flights,
       COUNT(AIR_SYSTEM_DELAY)    AS has_reason
FROM flights
GROUP BY 1
```

| late_15 | flights | has_reason |
|---|---|---|
| (ว่าง) = ไม่มีค่า `ARRIVAL_DELAY` | | |
| 0 = ถึงช้าไม่ถึง 15 นาที | | |
| 1 = ถึงช้าตั้งแต่ 15 นาที | | |

บันทึก query นี้ชื่อ `eda5_กฎสาเหตุ_<รหัสนักศึกษา>`

**สรุปกฎเป็นประโยคเดียว:** สาเหตุความล่าช้าถูกบันทึกก็ต่อเมื่อ ______________________________

> ค่าหายแบบนี้เรียกว่า **หายตามโครงสร้าง** — คอลัมน์นั้นไม่เกี่ยวกับแถวนั้นตั้งแต่แรก
> ถ้าเอาไปเติมด้วย 0 หรือค่าเฉลี่ยโดยไม่รู้กฎนี้ คุณจะสร้างข้อมูลปลอมขึ้นมา 37,299 แถว

**ค่าหายอีกสองที่ที่ควรรู้ไว้** (ถ้าคุณเลือกสองคอลัมน์นี้ในข้อ 5.2 คุณเจอเองแล้ว)
- `TAIL_NUMBER` หาย 62 แถว ทุกแถวเป็นเที่ยวบินที่ยกเลิก
- `LATITUDE` ของสนามบินต้นทางหาย 35 แถว มาจากสนามบินเล็ก 3 แห่ง (ECP, PBG, UST) — จดไว้ สัปดาห์ 9 ตอนทำแผนที่ จุดพวกนี้จะไม่ปรากฏ

## บันทึกการตัดสินใจ (Decision log) — เริ่มสัปดาห์นี้ เขียนต่อทุกสัปดาห์

ใส่ไว้ในกล่อง Markdown บนแท็บ `สำรวจข้อมูล flights` แล้ว **เขียนต่อท้ายทุกสัปดาห์ ห้ามลบ**

```markdown
## บันทึกการตัดสินใจ — flights

| สัปดาห์ | สิ่งที่พบ | หลักฐาน (กราฟหรือ query ไหน) | ตัดสินใจ | เหตุผล |
|---|---|---|---|---|
| 5 | ARRIVAL_DELAY หาย 1,354 แถว | query eda5_ค่าหาย + ตาราง ค่าหายอยู่กลุ่มไหน | ... | ... |
| 5 | สาเหตุความล่าช้าหาย 37,299 แถว | query eda5_กฎสาเหตุ | ... | ... |
| 5 | ... | | | |
```

ช่อง **ตัดสินใจ** เลือกจาก: ตัดแถวทิ้ง · เก็บไว้แต่แยกเป็นกลุ่มต่างหาก · เติมค่า (บอกด้วยว่าเติมอะไร) · ปล่อยว่างและจดไว้
ช่อง **เหตุผล** ต้องอ้างตัวเลขจากกราฟหรือ query ไม่ใช่ความรู้สึก

> ตัวอย่างการตัดสินใจที่ดี: "แยกเที่ยวบินยกเลิก 1,232 แถวออกจากการวิเคราะห์ delay เพราะมันไม่มีเหตุการณ์ให้วัด
> แต่เก็บไว้ต่างหากสำหรับคำถามว่าสายการบินไหนยกเลิกบ่อย"
> ตัวอย่างที่ไม่ดี: "ลบแถวที่มีค่าหายทั้งหมด" — คุณเพิ่งทิ้งข้อมูลเที่ยวบินยกเลิกทั้งหมดไปโดยไม่รู้ตัว

## บันทึกสัปดาห์นี้ (ต้องเขียน)

เปิดกล่อง Markdown บนแดชบอร์ดของคุณ (แท็บ `แดชบอร์ดหลัก`) แล้วเขียนต่อท้ายของเดิม

```markdown
## บันทึกสัปดาห์ที่ 5

(เขียนที่นี่ อย่างน้อย 60 ตัวอักษร)
```

**ห้ามลบบันทึกของสัปดาห์ก่อน** ตัวตรวจตรวจสะสม

สิ่งที่ควรเขียนถึง

- คุณจัดลำดับกราฟบนแดชบอร์ดอย่างไร และทำไมถึงเอาสิ่งที่อยู่บนสุดไว้บนสุด
- ค่าที่หายใน `flights` แบ่งได้กี่แบบ แต่ละแบบคุณจะทำอะไรกับมัน
- ก่อนทำตอนที่ 5 คุณคิดว่า "ค่าหาย = ข้อมูลเสีย" หรือไม่ ตอนนี้ยังคิดแบบนั้นอยู่ไหม เพราะอะไร

> เขียนสิ่งที่ **เห็น** ไม่ใช่สิ่งที่ **ทำ**
> "นับค่าหายเสร็จแล้ว" ไม่ได้บอกอะไรกับคนอ่าน
> "delay ขาเข้าหาย 1,354 แถว บวกกันแล้วเท่ากับยกเลิก 1,232 + เปลี่ยนเส้นทาง 122 พอดี เลยรู้ว่าไม่มีแถวไหนหายโดยไม่มีเหตุผล" บอก

## ส่งงาน

**ไม่ต้อง export ไม่ต้องอัปโหลดไฟล์** ระบบไปดึงแดชบอร์ดของคุณมาตรวจเอง

1. ตรวจให้แน่ใจว่าแดชบอร์ดชื่อ `csi414_<รหัส>` และคุณเป็นเจ้าของ
2. เขียนบันทึกใต้หัวข้อ `## บันทึกสัปดาห์ที่ 5` ในกล่อง Markdown
3. เข้า [ระบบส่งงาน](https://spu.minddatatech.com/assignment) แล้วกด **ลองตรวจ** แก้จนพอใจแล้วค่อยกด **ส่งงาน**

**ห้าม Publish** ปล่อยไว้เป็น Draft
