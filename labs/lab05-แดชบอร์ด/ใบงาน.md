## วัตถุประสงค์

## ตอนที่ 2 — เพิ่มตัวเลขสรุป และจัดหน้า (20 นาที)

1. สร้างกราฟชนิด **Big Number** ด้วย metric `SUM(Cost)` และ Time Range `No filter`
   ตั้งชื่อ `ค่าตั๋วรวมทั้งหมด <รหัสนักศึกษา>` แล้ววางบนแดชบอร์ด
2. เข้าโหมด **Edit dashboard** แล้วลากจัดใหม่: บนสุด = ตัวเลขสรุป · กลาง = กราฟที่อธิบายที่มา · ล่าง = ตารางรายละเอียด
3. ปรับขนาดกราฟให้กราฟที่สำคัญกว่าใหญ่กว่า

**ตอนนี้แดชบอร์ดของคุณต้องมีกราฟอย่างน้อย 4 รูป** (ตาราง · ตารางไขว้ · เส้น · แท่ง · ตัวเลขใหญ่ นับรวมกัน)

## ตอนที่ 3 — กล่อง Markdown ที่บอกสิ่งที่กราฟบอกไม่ได้ (15 นาที)

เพิ่มองค์ประกอบชนิด **Markdown** ลงบนแดชบอร์ด แล้วเขียนอย่างน้อย 4 อย่างนี้

```markdown
## <ชื่อแดชบอร์ดที่เป็นภาษาคน>

**คำถามที่ตอบ** ...
**ข้อมูล** tutorial_flights ชุดตัวอย่างทางการของ Apache Superset 2,954 แถว ช่วง ค.ศ. 2011
**หน่วย** ค่าตั๋วเป็นปอนด์ ...
**ไม่ครอบคลุม** ...
```

> **สิ่งที่กราฟบอกไม่ได้เลยคือที่มาของตัวเอง**
> ข้อมูลเก็บเมื่อไร ครอบคลุมช่วงไหน หน่วยคืออะไร นับใครบ้างและไม่นับใคร

## ตอนที่ 5 — สำรวจข้อมูลขั้นที่ 1: อะไรหายไป และหายเพราะอะไร (35 นาที)

ตั้งแต่สัปดาห์นี้ถึงสัปดาห์ 10 คุณจะสำรวจชุดข้อมูล **`flights`** (ฐานข้อมูล `examples`) ไปทีละขั้น
สัปดาห์ละหนึ่งคำถาม ทุกอย่างที่พบจะถูกจดลง **บันทึกการตัดสินใจ** ท้ายใบงาน และสะสมไปจนกลายเป็น
ใบสรุปส่งต่อให้คนที่จะเอาข้อมูลนี้ไปสร้างโมเดลในสัปดาห์ 10

**ชุดข้อมูล `flights`** — เที่ยวบินภายในสหรัฐอเมริกา ชุดตัวอย่างทางการของ Apache Superset
55,105 แถว · 44 คอลัมน์ · ครอบคลุม **4 วัน** (1–4 มกราคม 2015) · 14 สายการบิน · สนามบินต้นทาง 312 แห่ง
คอลัมน์ที่จะใช้สัปดาห์นี้: `CANCELLED` · `DIVERTED` · `DEPARTURE_DELAY` · `ARRIVAL_DELAY` · `CANCELLATION_REASON` · `AIR_SYSTEM_DELAY`

> **คุณไม่ต้องรู้จักข้อมูลนี้มาก่อน นั่นคือประเด็น**
> ในโปรเจกต์จริง ไม่มีใครเดินมาบอกว่าคอลัมน์ไหนหาย และหายเพราะอะไร คุณต้องหาเอง

### 5.1 สร้างแท็บใหม่ชื่อ "สำรวจข้อมูล flights" (5 นาที)

1. Edit dashboard → ลาก **Tabs** มาวาง → ตั้งชื่อแท็บแรก `แดชบอร์ดหลัก` (ย้ายของเดิมเข้าไป) และแท็บที่สอง `สำรวจข้อมูล flights`
2. กราฟทุกรูปของตอนที่ 5 วางในแท็บที่สอง

> แท็บนี้จะถูกนับเป็นข้อกำหนดของสัปดาห์ 6 ด้วย ทำวันนี้แล้วสัปดาห์หน้าไม่ต้องทำซ้ำ

### 5.2 นับก่อน: มีกี่แถวที่ "ไม่มีค่า" (10 นาที)

สร้างกราฟชนิด **Table** จาก dataset `flights` โดย **ไม่ใส่ Dimension** และใส่ metric 5 ตัวนี้
(ทุกตัวเป็นแบบ Simple ไม่ต้องเขียน SQL)

| metric | Aggregate | คอลัมน์ | ตั้งชื่อว่า |
|---|---|---|---|
| 1 | COUNT | `*` | `เที่ยวบินทั้งหมด` |
| 2 | COUNT | `DEPARTURE_DELAY` | `มีค่า delay ขาออก` |
| 3 | COUNT | `ARRIVAL_DELAY` | `มีค่า delay ขาเข้า` |
| 4 | COUNT | `CANCELLATION_REASON` | `มีเหตุผลยกเลิก` |
| 5 | COUNT | `AIR_SYSTEM_DELAY` | `มีสาเหตุความล่าช้า` |

Time Range `No filter` · ตั้งชื่อกราฟ `นับค่าที่มี <รหัสนักศึกษา>` แล้ววางบนแท็บ

**กติกาที่ต้องรู้:** `COUNT(*)` นับทุกแถว แต่ `COUNT(คอลัมน์)` นับเฉพาะแถวที่คอลัมน์นั้น **มีค่า**
ดังนั้น จำนวนที่หาย = `COUNT(*)` − `COUNT(คอลัมน์)`

**บันทึก** (คำนวณเอง)

| คอลัมน์ | มีค่า | หาย = 55,105 − มีค่า | หายกี่ % |
|---|---|---|---|
| `DEPARTURE_DELAY` | | | |
| `ARRIVAL_DELAY` | | | |
| `CANCELLATION_REASON` | | | |
| `AIR_SYSTEM_DELAY` | | | |

> ตัวเลข "หาย 1,354 แถว" ยังไม่ใช่ข้อค้นพบ มันเป็นแค่จุดเริ่มของคำถามว่า **1,354 แถวนั้นคือใคร**

### 5.3 หาว่าหายไปอยู่ตรงไหน (10 นาที)

ทำสำเนากราฟ Table เมื่อกี้ (Explore → Save as) แล้วเพิ่ม **Dimension** สองตัว: `CANCELLED` และ `DIVERTED`
ตั้งชื่อ `ค่าหายอยู่กลุ่มไหน <รหัสนักศึกษา>`

คุณจะได้ตาราง 3 แถว ให้ลอกตัวเลขลงตรงนี้

| CANCELLED | DIVERTED | เที่ยวบิน | มี delay ขาออก | มี delay ขาเข้า |
|---|---|---|---|---|
| 0 | 0 | | | |
| 0 | 1 | | | |
| 1 | 0 | | | |

**ตอบจากตาราง**

1. เที่ยวบินที่ **ไม่ยกเลิกและไม่เปลี่ยนเส้นทาง** มีค่า delay ครบทุกแถวหรือไม่ → _____
2. เที่ยวบินที่ **เปลี่ยนเส้นทาง** (DIVERTED = 1) มีค่า delay ขาเข้ากี่แถว → _____ ทำไมถึงเป็นแบบนั้น
3. เที่ยวบินที่ **ยกเลิก** มีค่า delay ขาออก _____ แถวจาก _____ แถว
   แปลว่ามีเที่ยวบินที่ออกไปแล้วแต่ถูกนับว่ายกเลิก จริงหรือไม่ และคุณจะเชื่อค่า delay ของ 37 แถวนั้นไหม
4. บวกกันดู: delay ขาเข้าที่หาย 1,354 แถว = ยกเลิก _____ + เปลี่ยนเส้นทาง _____ ใช่หรือไม่

> ถ้าบวกแล้วลงตัวพอดี แปลว่าคุณ **อธิบายค่าที่หายได้ทุกแถว** นี่คือสิ่งที่ต้องทำให้ได้ก่อนตัดสินใจอะไรกับมัน
> ค่าที่หายเพราะ "เที่ยวบินถูกยกเลิก" **ไม่ใช่ข้อมูลเสีย** มันหายเพราะไม่มีเหตุการณ์ให้วัด

### 5.4 ค่าที่หายเพราะกฎ ไม่ใช่เพราะเหตุการณ์ (10 นาที)

`AIR_SYSTEM_DELAY` หายไป 37,299 แถว มากกว่าครึ่ง แต่ไม่มีเที่ยวบินยกเลิกมากขนาดนั้น ต้องมีกฎอะไรบางอย่าง

1. เปิดกราฟ `นับค่าที่มี` ใน Explore แล้วเพิ่ม **Filter**: `ARRIVAL_DELAY` `>=` `15`
2. ดูค่า `เที่ยวบินทั้งหมด` กับ `มีสาเหตุความล่าช้า` หลังกรอง

| | ก่อนกรอง | หลังกรอง ARRIVAL_DELAY ≥ 15 |
|---|---|---|
| เที่ยวบินทั้งหมด | 55,105 | |
| มีสาเหตุความล่าช้า | | |

**สรุปกฎเป็นประโยคเดียว:** สาเหตุความล่าช้าถูกบันทึกก็ต่อเมื่อ ______________________________

> ค่าหายแบบนี้เรียกว่า **หายตามโครงสร้าง** — คอลัมน์นั้นไม่เกี่ยวกับแถวนั้นตั้งแต่แรก
> ถ้าเอาไปเติมด้วย 0 หรือค่าเฉลี่ยโดยไม่รู้กฎนี้ คุณจะสร้างข้อมูลปลอมขึ้นมา 37,299 แถว

**ค่าหายอีกสองที่ที่ควรรู้ไว้ (ไม่ต้องทำกราฟ)**
- `TAIL_NUMBER` หาย 62 แถว ทุกแถวเป็นเที่ยวบินที่ยกเลิก
- `LATITUDE` ของสนามบินต้นทางหาย 35 แถว มาจากสนามบินเล็ก 3 แห่ง (ECP, PBG, UST) — จดไว้ สัปดาห์ 9 ตอนทำแผนที่ จุดพวกนี้จะไม่ปรากฏ

## บันทึกการตัดสินใจ (Decision log) — เริ่มสัปดาห์นี้ เขียนต่อทุกสัปดาห์

ใส่ไว้ในกล่อง Markdown บนแท็บ `สำรวจข้อมูล flights` แล้ว **เขียนต่อท้ายทุกสัปดาห์ ห้ามลบ**

```markdown
## บันทึกการตัดสินใจ — flights

| สัปดาห์ | สิ่งที่พบ | หลักฐาน (กราฟไหน) | ตัดสินใจ | เหตุผล |
|---|---|---|---|---|
| 5 | ARRIVAL_DELAY หาย 1,354 แถว | ตาราง ค่าหายอยู่กลุ่มไหน | ... | ... |
| 5 | สาเหตุความล่าช้าหาย 37,299 แถว | ตาราง นับค่าที่มี + ตัวกรอง | ... | ... |
| 5 | ... | | | |
```

ช่อง **ตัดสินใจ** เลือกจาก: ตัดแถวทิ้ง · เก็บไว้แต่แยกเป็นกลุ่มต่างหาก · เติมค่า (บอกด้วยว่าเติมอะไร) · ปล่อยว่างและจดไว้
ช่อง **เหตุผล** ต้องอ้างตัวเลขจากกราฟ ไม่ใช่ความรู้สึก

> ตัวอย่างการตัดสินใจที่ดี: "แยกเที่ยวบินยกเลิก 1,232 แถวออกจากการวิเคราะห์ delay เพราะมันไม่มีเหตุการณ์ให้วัด
> แต่เก็บไว้ต่างหากสำหรับคำถามว่าสายการบินไหนยกเลิกบ่อย"
> ตัวอย่างที่ไม่ดี: "ลบแถวที่มีค่าหายทั้งหมด" — คุณเพิ่งทิ้งข้อมูลเที่ยวบินยกเลิกทั้งหมดไปโดยไม่รู้ตัว

## บันทึกสัปดาห์นี้ (ต้องเขียน)

เปิดกล่อง Markdown บนแดชบอร์ดของคุณ (แท็บ `แดชบอร์ดหลัก`) แล้วเขียนต่อท้ายของเดิม

```markdown
## บันทึกสัปดาห์ที่ 5

(เขียนที่นี่ อย่างน้อย 60 ตัวอักษร)
```

**ห้ามลบบันทึกของสัปดาห์ก่อน** ตัวตรวจตรวจสะสม

สิ่งที่ควรเขียนถึง

- คุณจัดลำดับกราฟบนแดชบอร์ดอย่างไร และทำไมถึงเอาสิ่งที่อยู่บนสุดไว้บนสุด
- ค่าที่หายใน `flights` แบ่งได้กี่แบบ แต่ละแบบคุณจะทำอะไรกับมัน
- ก่อนทำตอนที่ 5 คุณคิดว่า "ค่าหาย = ข้อมูลเสีย" หรือไม่ ตอนนี้ยังคิดแบบนั้นอยู่ไหม เพราะอะไร

> เขียนสิ่งที่ **เห็น** ไม่ใช่สิ่งที่ **ทำ**
> "นับค่าหายเสร็จแล้ว" ไม่ได้บอกอะไรกับคนอ่าน
> "delay ขาเข้าหาย 1,354 แถว บวกกันแล้วเท่ากับยกเลิก 1,232 + เปลี่ยนเส้นทาง 122 พอดี เลยรู้ว่าไม่มีแถวไหนหายโดยไม่มีเหตุผล" บอก
