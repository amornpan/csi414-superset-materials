## ตอนที่ 1 — เขียน SQL ที่สรุปข้อมูล (35 นาที)

1. เปิดเมนู **SQL ‣ SQL Lab**
2. เลือก Database `examples` และ Schema `public`
3. พิมพ์คำสั่งนี้ แล้วกด **Run**

```sql
SELECT DATE_TRUNC('month', "Travel Date") AS "เดือน",
       "Travel Class"                      AS "ชั้นโดยสาร",
       AVG("Cost")                         AS "ค่าตั๋วเฉลี่ย",
       COUNT(*)                            AS "จำนวนเที่ยว"
FROM tutorial_flights
GROUP BY 1, 2
ORDER BY 1
```

**บันทึกผล**

| คำถาม | คำตอบ |
|---|---|
| ผลลัพธ์ได้กี่แถว | |
| ข้อมูลดิบมีกี่แถว | |
| อัตราส่วนที่ลดลงเท่าไร | |

> **นี่คือเหตุผลทั้งหมดของการสรุปในฐานข้อมูล**
> ข้อมูลดิบ 2,954 แถวเดินทางผ่านเครือข่ายมาถึงเบราว์เซอร์ ช้ากว่าการส่งผลสรุปไม่กี่สิบแถวมาก
> และยิ่งข้อมูลใหญ่ขึ้น ความต่างนี้ยิ่งเป็นเรื่องคอขาดบาดตาย

## ตอนที่ 2 — บันทึกเป็น Dataset เสมือน (25 นาที)

1. เมื่อผลลัพธ์ถูกต้องแล้ว กด **Save ‣ Save dataset**
2. ตั้งชื่อ `สรุปค่าตั๋วรายเดือน <รหัสนักศึกษา>`
3. เปิด Dataset นั้นแล้วสร้างกราฟ **Line Chart**

| ช่อง | ค่าที่ตั้ง |
|---|---|
| X-axis | `เดือน` |
| Metrics | `AVG(ค่าตั๋วเฉลี่ย)` |
| Dimensions | `ชั้นโดยสาร` |
| X Axis Title / Y Axis Title | `เดือน` / `ค่าตั๋วเฉลี่ย (ปอนด์)` |

4. ตั้งชื่อ `ค่าตั๋วเฉลี่ยรายเดือนจาก SQL Lab <รหัสนักศึกษา>` บันทึกลงแดชบอร์ด **แท็บเจาะลึก**

> **การรัน SQL ทิ้งไว้เฉย ๆ ไม่ติดไปกับไฟล์ export**
> ถ้าไม่กด Save dataset ระบบตรวจจะไม่เห็นงานส่วนนี้เลย และคุณจะตกทั้งที่ทำแล้ว
> นี่คือจุดที่คนพลาดมากที่สุดในแล็บนี้


## ตอนที่ 3 — Semantic Layer: นิยาม metric ครั้งเดียว ใช้ทุกที่ (35 นาที)

1. ไปที่ **Datasets** หา `tutorial_flights` แล้วกดไอคอนดินสอเพื่อ **Edit dataset**
2. เปิดแท็บ **Metrics** แล้วกด **Add item**
3. ตั้งค่าตามนี้

| ช่อง | ค่าที่ตั้ง |
|---|---|
| Metric Key | `ค่าตั๋วเฉลี่ย` |
| Label | `ค่าตั๋วเฉลี่ย (ปอนด์)` |
| SQL Expression | `AVG("Cost")` |
| D3 Format | `,.1f` |
| Description | บอกว่านิยามนี้นับอะไรและไม่นับอะไร |

4. กด **Save**
5. กลับไปแก้กราฟเดิมของคุณอย่างน้อย **1 รูป** ให้เลือก metric จากรายการ
   `ค่าตั๋วเฉลี่ย (ปอนด์)` แทนที่จะสร้าง adhoc metric ใหม่

**เทียบสองวิธี**

| | เขียน AVG(Cost) ในแต่ละกราฟ | นิยาม metric กลางที่ Dataset |
|---|---|---|
| ตอนสร้างกราฟใหม่ | | |
| ตอนต้องเปลี่ยนนิยาม | | |
| ความเสี่ยงที่ตัวเลขจะขัดกันเอง | | |

> **นี่คือสิ่งที่เรียกว่า Semantic Layer**
> มันคือชั้นที่แปลจาก "คอลัมน์ในฐานข้อมูล" เป็น "ตัวเลขที่คนในองค์กรพูดถึง"
> เมื่อทุกกราฟเรียกนิยามเดียวกัน คำว่า "ค่าตั๋วเฉลี่ย" ในที่ประชุมจึงหมายถึงสิ่งเดียวกันจริง ๆ

## บันทึกสัปดาห์นี้ (ต้องเขียน)

เปิดกล่อง Markdown บนแดชบอร์ดของคุณ แล้วเขียนต่อท้ายของเดิม

```markdown
## บันทึกสัปดาห์ที่ 8

(เขียนที่นี่ อย่างน้อย 60 ตัวอักษร)
```

**ห้ามลบบันทึกของสัปดาห์ก่อน** ตัวตรวจตรวจสะสม ลบแล้วตกย้อนหลัง
เหมือนลบกราฟเก่าทิ้ง

สิ่งที่ควรเขียนถึง

- Dataset เสมือนต่างจากการเขียนสูตรซ้ำในแต่ละกราฟอย่างไร และข้อดีคืออะไร
- คุณย้ายสูตรอะไรไปเป็น metric กลาง และถ้าวันหนึ่งนิยามนั้นต้องเปลี่ยน คุณต้องแก้กี่ที่
- SQL Lab กับ Explore เหมาะกับงานคนละแบบอย่างไร ยกตัวอย่างงานที่ต้องใช้แต่ละอย่าง

> เขียนสิ่งที่ **เห็น** ไม่ใช่สิ่งที่ **ทำ**
> "ทำกราฟเส้นเสร็จแล้ว" ไม่ได้บอกอะไรกับคนอ่าน
> "เปลี่ยนจาก SUM เป็น AVG แล้วรูปเปลี่ยนไปคนละเรื่อง" บอก
